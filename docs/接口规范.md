## 〇、五层架构总览

```
┌──────────────────────────────────────────────────────────────────────┐
│  层 1: Web API (web/app.py)            13 个 REST 接口
│  层 2: LLM 服务 (llm_service.py)       语义分析 + 代码生成 + 后处理
```

## 步骤 A：数据库初始化（一次性，旁路）

### A.1 `build_database()` — 总入口

**模块**: `db_initializer.py`

**函数签名**:
```python
def build_database(db_path: str = DB_PATH, force: bool = True) -> None:
```

**输入**:
| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `db_path` | `str` | `resource/gee_oge.db` | 目标数据库路径 |
| `force` | `bool` | `True` | 是否删除旧库重建 |

**输出**: 无（控制台打印进度）

**示例**:
```python
# 重建默认数据库（首次初始化）
from db_initializer import build_database
build_database(force=True)
# [OK] 数据库已初始化: .../resource/gee_oge.db
# [OK] class_mapping: N 条
# [OK] gee_api_info: 1452 条
# [OK] oge_api_info: 478 条
# [OK] operator_mapping (Excel): 251 条
# [OK] operator_mapping (Python 实现): 92 条
```

### A.2 各子步骤接口

**`init_database(db_path, force=True)`**
- 建表（执行 `resource/db_schema.sql`）
- 输出: 无

**`import_class_mapping(conn)`**
- 导入 GEE↔OGE 类映射
- 输出: `int`（导入条数）

**`import_gee_api_info(conn)`**
- 从 `resource/gee.json` 导入 GEE API 元数据
- 输出: `int`（导入条数，应为 1452）

**`import_oge_api_info(conn)`**
- 从 `resource/oge.json` 导入 OGE API 元数据
- 输出: `int`（导入条数，应为 478）

**`import_operator_mapping_from_xlsx(conn)`**
- 从 `resource/gee_to_oge_matches.xlsx` 导入真 OGE 映射
- 内部调用 `_is_pseudo_oge_name()` 过滤伪映射、`_determine_mapping_type()` 判定类型
- 输出: `int`（导入条数）

**`import_native_python_implementations(conn)`**
- 从 `gee_python_functions.py` 和 `gee_unmatched_functions.py` 导入 Python 实现
- 使用 `_extract_function_source()` 基于 AST 提取源码
- 输出: `int`（导入条数，应为 ~92）

**`_is_pseudo_oge_name(oge_api_name) -> bool`**
- 识别伪映射占位符（以 `Python`、`print` 等开头）
- 输入: OGE API 名
- 输出: `True/False`

**`_determine_mapping_type(oge_apis, native_python=False) -> str`**
- 判定映射类型
- 输出: `"one_to_one"` / `"one_to_many"` / `"many_to_one"` / `"native_python"` / `"missing"`

**`_extract_function_source(file_path, func_name) -> str | None`**
- 用 AST 从 Python 文件中提取完整函数源码
- 输入: 文件路径 + 函数名
- 输出: 函数源码字符串（或 `None`）

### C.4 映射上下文构建 — `_build_mapping_context(dao, gee_code) -> str`

**输入**: DAO 实例 + GEE 代码
**输出**: 结构化文本

**示例**:
```
## ee.Geometry.Point
- GEE 描述: Constructs a Geometry with a single point.
- GEE 参数: coordinates: List, proj: String
- 映射类型: 一对一 (one_to_one)
- OGE API: Geometry.Point
- OGE 输入类型: List, String
- OGE 输出类型: Geometry
- OGE 示例代码: service.getProcess("Geometry.Point").execute([lng, lat], "EPSG:4326")

## 补充说明：FeatureCollection 构建
- 当 GEE 代码用 ee.FeatureCollection([f1, f2]) 从 Feature 列表构建时，
  应使用 FeatureCollection.loadFromFeatureList：
  fc = service.getProcess('FeatureCollection.loadFromFeatureList').execute([f1, f2])
  ...
```

### C.5 LLM 代码生成 — `llm.generate_oge_code(gee_code, mapping_context) -> Dict`

**输入**: GEE 代码 + 映射上下文
**输出**:
```json
{
  "oge_code": "import oge\noge.initialize()\nservice = oge.Service.initialize()\n...",
  "explanations": [
    "Step 1: 识别到 ee.Geometry.Point 构造",
    "Step 2: 使用 service.getProcess('Geometry.Point').execute([lng, lat], 'EPSG:4326')",
    "Step 3: ..."
  ],
  "warnings": ["filterDate 已自动补充第4参数 system:time_start"],
  "feasibility": "full_feasible"
}
```

**feasibility 取值**:
- `full_feasible`: 所有算子都有映射
- `partial_feasible`: 部分算子缺失，但核心功能可运行
- `infeasible`: 核心算子缺失

### C.6 后处理修正 — `llm._post_process_oge_code(code) -> str`

自动修正 5 类问题：
1. `oge.Service()` → `oge.Service.initialize()`
2. `oge.Geometry.Point([lng, lat])` → `service.getProcess("Geometry.Point").execute([lng, lat], "EPSG:4326")`
3. `getProcess("FeatureCollection")` → `getProcess("FeatureCollection.loadFromFeatureList")`
4. 关键字参数 → 位置参数（`geometry=`, `properties=`, `start=`, `end=`, `features=` 等）
5. `filterDate` 缺少第 4 参数时自动补充 `"system:time_start"`

## 附录：状态码速查

| 状态码 | 含义 |
|--------|------|
| 200 | 成功 |
| 400 | 请求参数错误（如 `gee_code` 为空） |
| 404 | 资源未找到（如 API 映射不存在） |
| 500 | 服务器内部错误 |
| 503 | LLM 服务不可用（`/api/convert-llm` 专用） |

## 附录：数据类型字典

- `mapping_type`: `"one_to_one"` | `"one_to_many"` | `"many_to_one"` | `"native_python"` | `"missing"`
- `feasibility`: `"full_feasible"` | `"partial_feasible"` | `"infeasible"`
- `verification_status`: `"manually_approved"` | `"pending"` | `"auto_verified"`
