# 01. GEE → OGE 六步迁移流程算法

## 目标

将 GEE JavaScript 脚本转换为 OGE Python 工作流，同时给出映射率、缺失 API 与可行性结论。统一入口为 `CaseStudyPipeline.run(gee_code)`。

## 总体流程

```text
输入 GEE 代码
  ↓
1. 语义抽象与步骤分解
  ↓
2. API 需求识别
  ↓
3. GEE → OGE API 匹配
  ↓
4. 步骤级 OGE 代码生成
  ↓
5. 可行性补全
  ↓
6. 工作流重构
  ↓
输出 OGE 代码、缺失报告、匹配率与可行性标签
```

## Step 1：语义抽象与步骤分解

**输入：** GEE JavaScript 字符串。  
**输出：** 任务目标、步骤列表、每一步代码片段和关键参数。

1. LLM 可用时，调用 `analyze_gee_code` 生成任务目标和语义步骤。
2. 执行“代码行覆盖校验”：去掉空行和注释后，比较原脚本与 LLM 返回的步骤代码；未覆盖的行追加至最后一个步骤，避免丢失可执行语句。
3. LLM 不可用或失败时，以单行 `// 注释` 作为步骤边界；没有注释时，整个脚本作为一个步骤。
4. 以规则提取数据源、波段、指数、坐标、日期范围、属性和主要操作等关键参数。

**覆盖校验伪代码：**

```python
original = non_empty_non_comment_lines(gee_code)
covered = set(non_empty_lines(step.code for step in llm_steps))
missing = [line for line in original if line not in covered]
if missing:
    llm_steps[-1].code += '\n' + '\n'.join(missing)
```

## Step 2：API 需求识别

**输入：** Step 1 的代码步骤。  
**输出：** 每步 API 清单、全量去重 API 清单和 API 数量。

先合并所有步骤代码进行全局类型推断，解决变量跨步骤使用的问题；再逐步提取 API。可识别：

- 构造调用：`ee.Image(...)`、`ee.FeatureCollection(...)`；
- 多级静态调用：`ee.Algorithms.CannyEdgeDetector(...)`；
- 地图和导出调用：`Map.xxx(...)`、`Export.xxx(...)`；
- 基于类型表的实例调用：`img.normalizedDifference(...)` → `ee.Image.normalizedDifference`；
- 链式实例调用：`img.select(...).subtract(...)`。

## Step 3：API 映射匹配

**输入：** 去重后的 GEE API 集合。  
**输出：** 每个 API 的映射详情、匹配率、缺失清单。

对每个 API 查询 SQLite 的 `operator_mapping` 表。匹配率计算为：

\[
match\_rate = \frac{N_{matched}}{N_{total}}
\]

其中 `one_to_one`、`one_to_many`、`many_to_one`、`native_python` 均计入已匹配；数据库无记录或映射类型为 `missing` 计为缺失。对于数据库缺失项，若 LLM 可用且语义匹配置信度不少于 0.6，则作为 `llm_semantic` 匹配补入结果。

## Step 4：步骤级代码生成

按映射类型套用代码模板：

| 映射类型 | 生成策略 |
| --- | --- |
| `one_to_one` | 生成一个 `service.getProcess("算子名").execute(...)` 调用 |
| `one_to_many` | 按 `combo_steps` 展开多个 OGE 算子调用 |
| `many_to_one` | 生成目标算子并保留上下文提示 |
| `native_python` | 注入数据库保存的 Python 函数源码 |
| `missing` | 输出缺失标记，不生成可执行算子 |

## Step 5：可行性补全

将缺失 API 分为阻断性与非阻断性：

| 类别 | 识别关键字 | 处理 |
| --- | --- | --- |
| 非阻断性 | `Map`、`print`、`Export` 等 UI/展示操作 | 用 `print`、注释或替代展示逻辑处理 |
| 阻断性 | `Image`、`Feature`、`Reducer`、`Classifier`、`Filter` 等分析对象 | 标记为阻断，建议寻找 OGE 算子或补充 Python 实现 |
| 辅助性 | 其他缺失 API | 建议用 Python 原生逻辑替代 |

当阻断性缺失集合非空时，整体为不可行；否则可行。LLM 可用时，会为缺失项附加 Python 实现建议、依赖和示例。

## Step 6：工作流重构

根据可行性输出三种结果：

| 条件 | `feasibility` | 输出 |
| --- | --- | --- |
| 存在阻断性缺失 | `infeasible` | 部分工作流 + 缺失报告 |
| 仅存在非阻断性缺口 | `partial_feasible` | 完整工作流，UI 部分降级 |
| 无缺失 | `full_feasible` | 完整工作流 |

重构时只保留一组 `import oge`、`oge.initialize()` 和 `service = oge.Service()` 初始化代码，然后按步骤顺序拼接生成片段。
